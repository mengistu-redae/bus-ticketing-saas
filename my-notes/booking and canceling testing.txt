## Book a seat as demo-customer

1. Go to http://localhost:3000/auth/login, log in as demo-customer / changeme, set a new password when prompted (forced reset on first login).
2. You'll land back on localhost:3000. Open DevTools (F12) → Console tab — it needs to be a tab on the localhost:3000 origin so fetch sends your session cookie automatically.
3. Run:
fetch('/api/bookings', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    tripId: '4a89f23c-b530-4f85-b138-322c787c1196',
    seatIds: ['ad33b711-c1cb-4958-9c14-467ffb9d07c5'],
    idempotencyKey: 'manual-test-1'
  })
}).then(r => r.json()).then(console.log)

4. Expect a 201-shaped JSON body with an id field — that's the booking id. Copy it.

(Optional sanity check anytime: fetch('/auth/me').then(r=>r.json()).then(console.log) shows who the session thinks you are.)


## Cancel the seat as demo-operator-admin — this is the actual test of today's fix

1. Open a private/incognito window or in the same console, log out of the customer session first:
fetch('/auth/logout', { method: 'Pref = '/auth/login')

2. log in as demo-operator-admin / changeme, reset password when prompted.
3. Back in the console, run (swap in the booking id from step 1.4):
fetch('/api/bookings/<BOOKING_ID>/cancel', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ reason: 'manual smoke test' })
}).then(r => r.json()).then(console.log)

How to read the result:
- Success → a JSON Cancellation object with a refundAmount (should be 500.00, 100% refund — the trip departs >24h out and we seeded that tier). This means TenantContext.require() resolved correctly — the org-claim fix works end-to-end.
- Failure → an empty error body / 500, because TenantContext.require() throws IllegalStateException when it can't resolve a tenant, and CancellationController has no handler for that exception. If you see this, the org-claim fix didn't take — worth telling me so I can dig back in.
