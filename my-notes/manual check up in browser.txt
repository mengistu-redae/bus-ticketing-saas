## manual check up in browser 
###################################
 in a real browser:

1. Open http://localhost/ (or http://localhost/auth/login) — this should redirect you to Keycloak's login page.
2. Log in as demo-customer / changeme123 (or demo-operator-admin / changeme123 for the staff side) — it's a two-step form: username first, then password.

5. Whatever the frontend exposes for trip search (if there's a UI page wired to /api/trips/search) should work normally through port 80.
6. Logging out should go back through Keycloak's end-session endpoint and land you logged out.

If anything looks off in the browser — a redirect loop, a blocked cookie, mixed content, etc. — let me know what you see and I'll dig in. Credentials are also in your bus-ticketing-demo-credentials memory if you need the Keycloak admin console login too.


## Manual browser check — nginx entry point (http://localhost)

1. Confirm the stack is up (only if you haven't already):
- Redis container: bus-ticketing-saas-redis-1 running
- nginx container: bus-ticketing-saas-nginx-1 running
- spring-boot-api (port 8081), node-bff (port 3000), native Keycloak (port 8080) all running

2. Open a fresh/private browser window (avoids stale cookies from earlier direct :3000 testing)

3. Go to http://localhost/
- Should redirect to node-bff's /auth/login, which redirects again to Keycloak's login page at localhost:8080/realms/bustix/...
- URL bar should now show localhost:8080, a login form with just a username field first

4. Log in
- Username: demo-customer → click Next/Sign In
- It'll ask for a password next (two-step form): changeme123
- (Or use demo-operator-admin / changeme123 to test the staff side instead)

5. After submitting the password
- Browser briefly hits localhost:3000/auth/callback (this is the one hop that bypasses nginx — expected, see earlier note), then lands back on http://localhost/

6. Verify the session
- Go to http://localhost/auth/me — should show JSON like {"authenticated":true,"user":{...preferred_username:"demo-customer"...}}

7. Try an API call through nginx
- Go to http://localhost/api/trips/search?origin=Addis%20Ababa&destination=Bahir%20Dar — should return JSON with the seeded "Demo Bus Co" trip, not an error page

8. Log out
- Logout is a POST-only route, so it needs a button/form in whatever frontend UI you have — a plain URL visit to /auth/logout won't work (that's a GET, correctly 404s). If there's no frontend page yet, you can skip this step or trigger it via the browser devtools console: fetch('/auth/logout', {method:'POST'}).then(() => location.reload())

What "broken" would look like: a redirect loop, a blank/error page instead of Keycloak's login form, "session invalid" after login, or /api/... calls returning connection errors instead of JSON. If you see any of that, tell me exactly what page/error you hit and I'll dig in.
